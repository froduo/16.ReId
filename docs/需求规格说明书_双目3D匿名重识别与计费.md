## 1. 引言

### 1.1 背景

现有客流系统基于单目 RTSP 画面，通过 `PersonDetector`（YOLO/TensorRT）→ `PersonTracker`（卡尔曼 + IoU + ReID）
→ [`ZoneMonitor`](../CameraViewer_dongqia/src/zonemonitor.h:82) 的 **A/B 端点 Y 坐标穿越**判定上下车，
身份由 [`VisitorRegistry`](../CameraViewer_dongqia/src/visitorregistry.h:30) 维持，ReID 特征为
[`ReIDExtractor`](../CameraViewer_dongqia/src/reidextractor.h:6) 的 HSV 直方图。

公交上下车场景存在以下痛点：

- **单目透视歧义**：门区俯视/斜视下，2D 像素穿越难以区分「上车」与「下车」，尤其多人并排、遮挡时；
- **人脸不可见**：车门正上方俯视看不到人脸，人脸 ReID 不可用；
- **相似衣物**：公交场景同款工装/校服多，纯颜色 ReID 误匹配率高；
- **计费争议**：需要可审计、可复核的上下车时间与票务绑定链路。

### 1.2 目标

- 以**双目深度相机**在门区完成 **3D 轨迹 + 身高/体型测量**，实现无遮挡歧义的上下车方向判定；
- 以**头肩、肩部衣物颜色/纹理、发型帽子、步态**等特征做**动态加权匿名重识别**，上车建临时 ID、下车从未下车库匹配；
- **票务/扫码强绑定** + **置信度分级** + **人工兜底**，形成"相机弱识别 + 票务强绑定 + 云端计费 + 人工复核"的组合方案；
- 端到端延迟 < 200 ms，计费准确率 ≥ 99.9%（结合票务）。

### 1.3 范围

| 范围 | 说明 |
|------|------|
| 在范围内 | 门区双目相机接入、3D 事件判定、匿名特征提取/匹配、票务绑定、计费记录生成、置信度分级、上报与人工复核接口 |
| 不在范围内 | 票务系统本身、云端计费服务端实现（仅定义接口与报文）、车辆定位系统本身 |

### 1.4 术语与缩略语

| 术语 | 说明 |
|------|------|
| 虚拟门线 | 门框投影到地面的分割线，法线沿通行方向，用于判定跨越方向 |
| 未下车乘客库 | 已上车但尚未匹配到下车的临时乘客集合 |
| 临时乘客 ID | 上车时创建的匿名 ID（如 `P_1024`），下车匹配后可与 `ticket_id` 绑定 |
| 动态加权 | 基础权重 `w_k` × 质量置信度 `q_k` 的实时调整机制 |
| 兜底 | 自动匹配失败时的人工复核 / 规则补扣 |

### 4.2 俯视条件下的乘客特征提取

> 由于看不清人脸，**人脸权重设为 0**。重点提取以下特征（基础权重为**建议初值**，须动态调整）：

| 特征 | 说明 | 基础权重建议 |
|------|------|:------------:|
| 身高/体型/深度体积 | 地面到头顶高度、身体厚度、体积 | **0.30** |
| 肩宽/肩形 | 肩部点云宽度、曲率、左右肩比例 | **0.20** |
| 肩部衣物颜色 | HSV/Lab 直方图，**肩部环带**采样 | **0.20** |
| 衣物纹理/图案 | LBP、CNN embedding、条纹/格子等 | **0.15** |
| 头部发型/发色/帽子 | 头顶区域分类 | **0.10** |
| 步态/速度/轨迹 | 步速、步频、进入门区姿态 | **0.05** |

| 编号 | 需求 |
|------|------|
| **REQ-FEAT-01** | 提供上述 6 类特征提取接口，人脸权重恒为 0 |
| **REQ-FEAT-02** | 颜色特征采用 **肩部环带采样**（避免门区顶部/地面的背景污染） |
| **REQ-FEAT-03** | 纹理特征：LBP + CNN embedding 至少实现其一作为可插拔后端 |
| **REQ-FEAT-04** | 特征模板支持**多帧平均**（沿用 `REID_HISTORY_SIZE=5` 思路）以降低单帧噪声 |

**与现有实现的映射：** [`ReIDExtractor`](../CameraViewer_dongqia/src/reidextractor.h:6) 由单一 HSV 直方图
扩展为**多特征提取器**（建议拆分为 `FeatureBundle`）：

```cpp
struct FeatureBundle {
    cv::Mat  colorHist;   // 肩部环带 HSV/Lab
    cv::Mat  lbp;         // 纹理
    cv::Mat  cnnEmbed;    // 可选 CNN/OSNet embedding
    float    height;      // 身高（m，来自深度/点云）
    float    shoulderWidth;
    float    bodyDepth;
    float    volume;
    int      hairClass;   // 发型/帽子分类
    float    gaitSpeed;   // 步态
    float    quality;     // 综合质量置信度 q
};
```

### 4.3 动态加权匿名重识别

**相似度融合公式：**

```
S(i,j) = Σ_k  w_k · q_k · s_k(i,j)  /  Σ_k  w_k · q_k
```

其中：

- `w_k`：第 k 类特征**基础权重**（见 §4.2 表）；
- `q_k`：**当前质量置信度**（深度质量、光照、遮挡程度等）；
- `s_k(i,j)`：**相似度**（身高差、颜色余弦相似度、纹理相似度等）。

**动态策略：**

| 场景 | 权重调整 |
|------|----------|
| 深度质量高 | 身高、肩宽权重**升高** |
| 光照稳定、衣物清晰 | 颜色、纹理权重**升高** |
| 拥挤遮挡 | 几何、时空权重升高，**纹理权重降低** |
| 有票务绑定 | **直接强匹配**，相机只做校验 |

| 编号 | 需求 |
|------|------|
| **REQ-REID-01** | 实现 `w_k`（基础权重）可配置，`q_k`（质量置信度）实时估计 |
| **REQ-REID-02** | 实现加权融合相似度 `S(i,j)`，输出**每类特征**的可解释分量（用于审计） |
| **REQ-REID-03** | 质量估计算子：深度有效像素比例、点云完整度、光照均值/方差、遮挡检测 |
| **REQ-REID-04** | 票务强绑定时绕过外观阈值（`S` 不参与拒绝判定，仅记录校验分） |
| **REQ-REID-05** | 权重组可**在线热更新**（云端模型/参数下发） |

**与现有实现的映射：** [`VisitorRegistry`](../CameraViewer_dongqia/src/visitorregistry.h:30) 当前以单一
`cv::Mat feature` + `float similarity()` 工作，需升级为**多特征 `FeatureBundle`**、`resolveEx()` 返回
**加权融合相似度 + 各分量**，并支持 `q_k` 参与的自适应阈值。

### 4.5 上下车匹配流程

**上车流程：**

1. 检测上车事件；
2. 创建临时乘客 ID；
3. 提取并保存特征模板；
4. 若刷卡/扫码/NFC 在 **±1–2 s** 时间窗内发生，绑定 `ticket_id`；
5. 加入「**未下车乘客库**」。

**下车流程：**

1. 检测下车事件；
2. 提取特征；
3. 与「未下车乘客库」计算**综合相似度**；
4. 多人同时下车时构建**代价矩阵**，用**匈牙利算法**全局匹配；
5. **约束**：`下车时间 > 上车时间`、行程时长合理、同一车辆/线路合理；
6. 匹配成功 → 生成**行程记录**并计算费用；
7. 匹配失败 → 用票务最后未下车记录 / 人工复核 / 按规则补扣。

| 编号 | 需求 |
|------|------|
| **REQ-MATCH-01** | 实现「未下车乘客库」的增删查与生命周期管理 |
| **REQ-MATCH-02** | 下车时构建代价矩阵（`1 - S`），匈牙利算法求全局最优匹配 |
| **REQ-MATCH-03** | 施加时间/线路/车辆**合理性约束**，过滤非法匹配 |
| **REQ-MATCH-04** | 匹配失败走**兜底策略链**：票务最后未下车记录 → 人工复核 → 规则补扣 |
| **REQ-MATCH-05** | 记录每次匹配的**候选列表 + 分量得分**，供审计与人工复核 |

**匹配阈值：**

| 区间 | 处置 |
|------|------|
| `S > 0.85` | **自动匹配** |
| `0.65 < S < 0.85` | **候选匹配**，票务校验或人工复核 |
| `S < 0.65` | **拒绝**，进入异常队列 |

### 4.7 置信度分级与人工兜底

| 编号 | 需求 |
|------|------|

| **REQ-CONF-03** | 提供**人工复核界面**（确认/改绑/拒绝），复核动作写入审计日志 |

| **REQ-CONF-05** | 全链路**审计日志**：原始事件、候选、匹配、计费、复核操作 |

## 6. 关键难点与对策

| 难点 | 对策 |
|------|------|
| 多人紧贴、遮挡 | 双目点云分割 + 头肩检测 + 多帧融合 + 等待分开 |
| 相似衣物 | 提高身高、肩宽、体型权重；票务强绑定 |
| 儿童 / 抱小孩 | 身高 + 肩宽 + 票务辅助；单独模型阈值 |
| 戴帽、背包、弯腰 | 多帧特征平均；降低单帧影响 |
| 中途换衣 | 几何特征主导，颜色权重降低 |
| 上车时间短 | 快速注册，使用前几帧稳定特征 |
| 计费争议 | 置信度分级、人工复核、日志审计 |

| **REQ-PRIV-03** | 原始视频**边缘短存**，默认不上云 |
| **REQ-PRIV-04** | 传输与存储**加密** |
| **REQ-PRIV-05** | 告知乘客并符合《个人信息保护法》等要求 |
| **REQ-PRIV-06** | 提供**人工复核与申诉通道** |

## 8. 非功能需求

| 编号 | 需求 |
|------|------|
| **REQ-NFR-01** | 端到端延迟 **< 200 ms**（边缘事件 → 上传） |

## 12. 结论

该方案不依赖人脸，而是用**双目深度相机**做 **3D 轨迹和身高/体型测量**，用**头肩、肩部衣物颜色、纹理、
发型帽子、步态**等多特征**动态加权**做匿名重识别。上车时创建临时 ID，下车时从未下车库中匹配，
结合刷卡/扫码**强绑定**，生成精确的上下车时间与计费记录。它是
「**相机弱识别 + 票务强绑定 + 云端计费 + 人工兜底**」的组合方案，科学、可落地，也符合隐私合规要求。
