# 门线穿越检测（DoorCounter v6）与乘车数据存储

> 本次改造把「检测区域（通道多边形）」升级为**虚拟门线（Door Line）**判定，
> 并引入 DoorCounter v6 的**四层容错恢复机制**；同时新增
> **每站上下车人数 / 车厢内人数**的数据库持久化（默认 SQLite，可切换 PostgreSQL）。

---

## 一、从「检测区域」到「检测门线」

### 1.1 几何定义

- 旧逻辑：人体框与「通道多边形外接矩形」求交集，且中心点需**完整穿越整个区域**才判定上下车
  → 要求严格、样本不足、擦边误判多。
- 新逻辑：为每个区域派生一条**虚拟门线**，只要乘客中心点**跨越门线**即判定一次上/下车。

门线来源（[`RegionManager::regionDoorLine()`](../CameraViewer/src/regionmanager.cpp:100)）：

1. 若区域显式配置了门线（`DetectionRegion::shape == RegionShape::DoorLine`，且
   [`lineStart`/`lineEnd`](../CameraViewer/src/regionmanager.h:26) 有效）→ 直接使用；
2. 否则由多边形外接矩形派生：**门线位于外接矩形纵向中线，横跨左右边界**。
   → 旧工程已绘制的通道区域**零配置升级**为门线检测。

门线几何与侧别定义见 [`DoorLine`](../CameraViewer/src/zonemonitor.h:105)：

```
signedSide(p) = (p - A) · normal        // normal 恒指向图像下方(Y增大)
  > 0 → B 侧（内侧/车门内）
  < 0 → A 侧（外侧/车门外）
```

方向语义：默认 `entryDirection == TopToBottom` 时 **A→B 跨越 = 上车**；`BottomToTop` 时取反
（见 [`ZoneMonitor::emitCrossing()`](../CameraViewer/src/zonemonitor.cpp:300)）。

### 1.2 持久化

`regions.json` 新增 `shape` / `lineStart` / `lineEnd` 字段
（[`RegionManager::saveRegions()`](../CameraViewer/src/regionmanager.cpp:118) /
[`loadRegions()`](../CameraViewer/src/regionmanager.cpp:170)），向后兼容旧文件。

## 二、DoorCounter v6：四层容错恢复机制

俯视场景中乘客上下车会因遮挡、转身、漏检造成轨迹中断。仅靠「实时判断」会漏检/误判，
因此按置信度从高到低设计了四层恢复（[`RecoveryLayer`](../CameraViewer/src/zonemonitor.h:37)）：

| 层 | 名称 | 触发时机 | 做法 | 置信度 |
|---|---|---|---|---|
| L1 | **实时判断** | 正常跟踪 | 逐帧计算中心点相对门线的**有符号距离**，侧别 A/B 翻转且连续 `sideConfirmFrames` 帧确认、投影落在门线段内 → 立即计一次跨越 | 1.00 |
| L2 | **惯性滑行** | 目标在门线处短暂丢失 | 按最近速度 `pos + v·Δt` 外推；若预测位置已到门线另一侧且速度朝向该侧、在 `inertiaMaxMs` 内 → 判为已完成跨越 | 0.80 |
| L3 | **轨迹拼接** | 轨迹被遮挡/换 ID 打断 | 断裂时记录「锚点」（外侧起点侧别 + 速度预测位置）→ 新轨迹在 `stitchWindowMs` 时间窗、`stitchRadius` 空间邻域内、且方向一致时，**继承锚点的外侧起点**把半程拼成一次完整穿越 | 0.75 |
| L4 | **兜底策略** | 一侧出现、另一侧消失 | 轨迹移除时，若「首次确认侧别」≠「最后一次确认侧别」，即使实时确认未完成也按兜底计入 | 0.60 |

实现要点（[`ZoneMonitor::processFrame()`](../CameraViewer/src/zonemonitor.cpp:517)）：

- **死区**（`m_lineDeadband`）：`|signedSide| < deadband` 时不改变侧别，抑制在门线上抖动。
- **整段采样窗口**：人体进入门线「接近走廊」（`|signedSide| ≤ corridorHalf` 且投影在门线段内）
  时开始逐帧采样人物裁剪图 / 整帧序列，离开走廊停止；跨越时整段随事件一起交上层保存。
- **重新武装**：一次跨越结算后，乘客需**离开走廊**（`> corridorHalf*1.6`）才能再次武装，
  避免同一人来回擦线被重复计数。
- **防误判**：同人反向穿越冷却窗口（`reverseCooldownMs`，默认 8s）内的反向跨越被抑制。
- 事件携带诊断字段 [`ZoneEvent`](../CameraViewer/src/zonemonitor.h:58)：`recoveryLayer` /
  `recoveryName` / `crossNormX,Y` / `sideEnter` / `sideExit` / `confidence` / `coasted` /
  `stitched` / `fallback`，便于日志复盘与阈值标定。

### 2.1 可调参数

| 参数 | 接口 | 默认 | 说明 |
|---|---|---|---|
| 死区 | [`setLineDeadband()`](../CameraViewer/src/zonemonitor.h:200) | 0.006 | 门线附近不改侧别的垂直距离（归一化） |
| 走廊半宽 | [`setCorridorHalfWidth()`](../CameraViewer/src/zonemonitor.h:202) | 0.16 | 决定何时开始/停止整段采样 |
| 侧别确认帧 | [`setSideConfirmFrames()`](../CameraViewer/src/zonemonitor.h:204) | 2 | 侧别翻转连续确认帧数 |
| 惯性时长 | [`setInertiaMaxMs()`](../CameraViewer/src/zonemonitor.h:206) | 700ms | L2 惯性滑行最大外推时长 |
| 拼接时间窗 | [`setStitchWindowMs()`](../CameraViewer/src/zonemonitor.h:208) | 1500ms | L3 轨迹拼接有效窗口 |

`setChannelZones()` / `setConfirmFrames()` / `setMinOverlapArea()` 等旧接口保留，保证
[`offlinedetectform.cpp`](../CameraViewer/src/offlinedetectform.cpp:60) 与
[`offline_clip_check.cpp`](../offline_clip_check.cpp:120) 无需改动即可复用。

## 三、乘车数据存储（每站上下车人数 + 车厢内人数）

### 3.1 抽象层

[`TripDataStore`](../CameraViewer/src/tripdatastore.h:51) 定义统一接口，后端可插拔：
`create("sqlite")` / `create("postgresql")`（工厂见
[`TripDataStore::create()`](../CameraViewer/src/tripdatastore.cpp:24)）。

[`SqlTripStore`](../CameraViewer/src/tripdatastore.cpp:40) 用 Qt SQL 统一实现，
SQLite 与 PostgreSQL 仅**驱动**（`QSQLITE`/`QPSQL`）与**建表自增列**（`AUTOINCREMENT`/`BIGSERIAL`）不同。

### 3.2 表结构

```sql
trips           (trip_id PK, vehicle_id, started_at, ended_at)
stop_stats      (trip_id, station_id, station_name,
                 boarding, alighting, onboard, updated_at,
                 PRIMARY KEY(trip_id, station_id))
passenger_events(seq 自增, trip_id, station_id, station_name,
                 passenger_id, event_type, recorded_at)
```

- `stop_stats` 即「**每一站的上下车人数 + 车厢内人数快照**」；
- `passenger_events` 为逐条事件流水，便于审计与回溯。

核心写入 [`SqlTripStore::applyStopEvent()`](../CameraViewer/src/tripdatastore.cpp:230)：
在同一事务内 upsert `stop_stats`（上下车累加、`onboard` 按 上车+1 / 下车-1 更新）并追加事件。

### 3.3 接入主流程

[`MainWindow::initTripStore()`](../CameraViewer/src/mainwindow.cpp:1754) 在启动时打开数据库、
开始一趟行程（`TRIP-<时间戳>`）；上/下车事件中分别调用
`recordBoarding()` / `recordAlighting()` 并刷新「车厢内: N」显示
（[`updateOnboardLabel()`](../CameraViewer/src/mainwindow.cpp:1810)）。
站点可运行期切换：[`setCurrentStation()`](../CameraViewer/src/mainwindow.cpp:1801)。

配置项见 [`AppConfig`](../CameraViewer/src/app_config.h:108)（`TripDb` 段）：

```ini
[TripDb]
Backend=sqlite               ; 或 postgresql
Path=./trip_data/bus_trips.db
Host=127.0.0.1
Port=5432
Name=bus
User=postgres
Password=
VehicleId=BUS-01
StationId=STATION-01
StationName=1号站
```

### 3.4 切换到 PostgreSQL

仅需改配置（无需改业务代码）：

```ini
[TripDb]
Backend=postgresql
Host=10.0.0.20
Port=5432
Name=bus_fleet
User=bus
Password=******
```

> 依赖 Qt 的 `QPSQL` 插件（已确认本机存在 `libqsqlpsql.so`）。
> 若插件缺失，`open()` 会返回明确错误并保留 SQLite 可用性。

## 五、验证与调参建议

1. 首次运行绘制/沿用现有通道区域即可（自动派生门线）；如门线位置不理想，可在
   `regions.json` 中显式写入 `shape=DoorLine` 与 `lineStart/lineEnd`。
2. 观察日志中 `[ZoneMonitor] CROSSING DECISION [Lx...]` 与 `recoveryName`，
   统计各恢复层的占比：L1 应占多数；L2/L3/L4 过多说明检测/跟踪召回不足，应优先调整
   检测阈值与跟踪 `maxMissed`。
3. 可通过 `setLineDeadband()` / `setSideConfirmFrames()` 抑制抖动误报；
   通过 `setInertiaMaxMs()` / `setStitchWindowMs()` 权衡漏检与误检。
4. 数据校验：
   `sqlite3 build-main-debug/trip_data/bus_trips.db "SELECT * FROM stop_stats;"`。

## 六、虚拟门线可视化

为便于现场确认门线位置是否准确，门线在**实时画面**与**主界面叠加层**两处都会绘制：

1. **视频帧叠加（含保存的图片/视频）** — [`MainWindow`](../CameraViewer/src/mainwindow.cpp:1556)
   在绘制区域多边形后，按 [`RegionManager::regionDoorLine()`](../CameraViewer/src/regionmanager.cpp:100)
   绘制：亮青色粗实线（带外发光）+ 两端圆点 + 中点法向刻度 + `DOOR 上车↓ / DOOR 下车↑` 标注。
   因此录制的「上/下车整段视频」中也带有门线，便于离线复核。
2. **主界面 ImageView 叠加** — [`ImageView::setDoorLines()`](../CameraViewer/src/imageview.cpp:107)
   与 [`paintEvent()`](../CameraViewer/src/imageview.cpp:459) 绘制门线（亮青实线 + 两端点 + 中点刻度）。
   由 [`MainWindow::refreshRegionOverlays()`](../CameraViewer/src/mainwindow.cpp:1243) 在
   加载区域、绘制/清空区域时统一刷新（同时刷新区域多边形与门线）。

> 门线由区域自动派生，无需额外绘制操作；若要自定义门线位置/角度，
> 可在 `regions.json` 中把该区域改为 `"shape": "DoorLine"` 并写入 `lineStart` / `lineEnd`。
