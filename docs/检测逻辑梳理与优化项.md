## 一、当前检测逻辑全景（数据流）

```
摄像头(RTSP 1920x1080@25fps)
      │  CameraController::getFrame()
      ▼
GrabThread::run()                     ← 采集线程（独立 QThread）
   ├─ 每 500 帧打印帧率日志
   ├─ 每 5 帧 emit rawFrameGrabbed(frame.clone())   ← 整帧深拷贝(≈6MB)
   ├─ BackgroundModel::update(frame)                ← 仅“画面基本无人”时学习背景
   └─ 检测管线：
        PersonDetector::detect(frame)               ← TensorRT yolo26n / OpenCV-DNN
        PersonTracker::update(dets, frame, reid)     ← 卡尔曼+IoU+ReID 多阶段匹配
        emit frameProcessed(img, persons)            ← 背压：UI busy 时丢弃本帧显示
      ▼
MainWindow::onFrameProcessed()        ← UI 主线程
   ├─ ZoneMonitor::processFrame(...)                 ← 【状态机A】
   │     └─ 命中区域→开始保存；离开区域→按中心点方向判 上车/下车
   │        emit boardingEvent / alightingEvent
   ├─ 【状态机B】自身的 RegionCrossState (Outside/Entering/Inside/Exiting)
   │     ├─ 进入确认(3帧)→ matchOrCreateVisitor()→ 访客V##、saveReidImage("ENTER")
   │     ├─ 区域内停留→ saveVisitorFrame()→ visitor_V##/*.jpg
   │     └─ 离开确认(3帧)→ updateVisitorExit()→ saveReidImage("EXIT")
   ├─ 上车事件(状态机A)→ PassengerBook::registerBoarding()→ 乘客P##、保存上车整段序列
   ├─ 下车事件(状态机A)→ IdentityMatchWorker::submit()→ 后台线程整段序列比对
   │        → applyAlightingMatch()：命中/回退/异常
   └─ 自动保存每帧显示图（SaveImageWorker，异步）
```

### 关键实现细节

| 阶段 | 位置 | 说明 |
|---|---|---|
| 采集 | [`GrabThread::run()`](../CameraViewer/src/grabthread.cpp:35) | 25fps；UI 帧每 5 帧发一次；背压丢帧 |
| 检测 | [`PersonDetector::detect()`](../CameraViewer/src/persondetector.cpp:89) | TRT `yolo26n`，conf=0.45，小目标过滤（高度比≥0.08、面积比≥0.005）|
| 跟踪 | [`PersonTracker::update()`](../CameraViewer/src/persontracker.cpp:402) | IoU→卡尔曼预测IoU→ReID 三阶段；丢失>30帧入画廊(10s) |
| 区域判定A | [`ZoneMonitor::processFrame()`](../CameraViewer/src/zonemonitor.cpp:302) | **人体框 ∩ 区域外接矩形**是否有交集；方向由**中心点是否越过区域中心线**决定 |
| 区域判定B | [`MainWindow::onFrameProcessed()`](../CameraViewer/src/mainwindow.cpp:1166) | **中心点是否落在多边形内**；Outside→Entering→Inside→Exiting 状态机 |
| 特征 | [`ReIDExtractor::extract()`](../CameraViewer/src/reidextractor.cpp:132) | HSV 颜色(15×8×8 上/下半身)+梯度纹理(18)+身形；BG 掩码剔除背景 |
| 上车台账 | [`PassengerBook::registerBoarding()`](../CameraViewer/src/passengerbook.cpp:38) | 记录整段序列特征 |
| 下车比对 | [`IdentityMatchWorker`](../CameraViewer/src/identitymatchworker.cpp:30) | 后台线程；探针每帧取与模板组最优后平均（best-avg）|
| 结算 | [`MainWindow::applyAlightingMatch()`](../CameraViewer/src/mainwindow.cpp:321) | 命中 / 回退(track 身份) / 异常 |

## 三、问题清单与优化项

> 优先级：P0=影响主流程正确性，先做；P1=显著提升鲁棒性；P2=工程/可观测性。

### P0-1 存在**两套并行的状态机与两套 ID**，身份链路混乱
- 现状：MainWindow 有自己的 `RegionCrossState`+访客 `V##`（[`matchOrCreateVisitor`](../CameraViewer/src/mainwindow.cpp:867)），ZoneMonitor 另有 `CaptureState`+访客 `V#`（[`matchOrCreateVisitor`](../CameraViewer/src/zonemonitor.cpp:100)）。二者各自自增、互不统一（日志里同一人可同时是 V41 与 V3）。
- 后果：`saveReidImage` 的 `person_##` 与台账 `P##` 对不上；下车回退身份（track→visitor）经常指向不在车乘客 → 大量“异常下车”。
- 优化：**合并为单一身份服务**（IdentityService）：以 `trackId → visitorId` 唯一映射为主键；ZoneMonitor 不再自建 visitor，直接使用 MainWindow 的 visitorId；上/下车事件只在一个地方产生。

### P0-2 上车/下车**方向判定过于瞬时、脆弱**
- 现状：ZoneMonitor 用“人体框 ∩ **外接矩形** + 中心点是否越过**中心线**”（[`finalizeCapture`](../CameraViewer/src/zonemonitor.cpp:195)）；MainWindow 用“中心点是否在多边形内 + 3 帧确认”。而 `overlap` 常为 1e-4（擦边），enter→exit 仅 ~1s。
- 后果：方向样本不足 → 误判/漏判（`Discard crossing` 43 次）；上车事件 enter/exit 几乎同帧。
- 优化：
  1. 用**中心点轨迹线性拟合斜率**判定方向（对区域内中心点 y 序列做回归），并要求 `|Δy| ≥ 阈值` 且 `持续帧数 ≥ N`；
  2. 相交判定改为**真实多边形包含/面积占比**（人体框中心在区域内 或 交并比≥阈值），替代“外接矩形擦边”；
  3. 引入**进入前 N 帧轨迹**做多线索投票，避免单帧抖动；
  4. 参数化（最小位移、最小停留时间、确认帧数）并暴露到设置界面。

### P0-3 ReID 外观比对在本场景**不可用**（已详证）
- 现状：手工描述子同人/异人分数重叠（V41↔V43 同人 0.85 vs V45↔V43 异人 0.86）；预训练 OSNet 用紧致框同样重叠（0.868 vs 0.897）。阈值 0.70 本质不可达（已临时下调 0.65）。
- 后果：`ALIGHTING matched = 0`，几乎全靠回退/异常路径。
- 优化：
  1. **降低对图像 ReID 的依赖**：上车登记/下车结账以**轨迹身份**（track→visitor）为主，ReID 仅作“校验/补救”；
  2. 若仍要视觉 ReID：必须**本域微调**（采集本相机数据训练/微调后再标定阈值），并配合**质心 + 裕度**（top1−top2≥margin）与 **DTW 序列对齐**替代 best-avg；
  3. 裁剪与特征**统一**：用检测框（去掉 0.3 padding）、确保 BG 掩码生效、上下半身比例按框长宽比自适应。

### P1-1 跟踪参数与 25fps 不匹配
- 现状：`maxMissed=30`（25fps≈1.2s）、`galleryReidThreshold=0.72`（基于弱特征，[`tryReidFromGallery`](../CameraViewer/src/persontracker.cpp:359) 还叠加 `dist<maxDist=10*框尺寸`）。
- 后果：短暂遮挡即丢 track→入画廊→重建（`New visitor` 178 次）；弱特征导致画廊匹配要么失败要么误合并。
- 优化：按**时间**设定丢失阈值（如 3s）；画廊匹配**先按时间+位置**强约束，再按外观；输出 bbox 用卡尔曼平滑以减小抖动（缓解 overlap 微小问题）。

### P1-2 检测召回与算力
- 现状：全帧 1920×1080 每帧检测 + 每个 det 每帧提 61478 维手工特征 + 背景前景分割；`NO detections at all` 频繁。
- 优化：
  1. **ROI 检测**：仅在区域及其上方/下方扩展带内检测（提升小目标召回与速度）；
  2. 区域内特征**降频采样**（如每 2~3 帧）；
  3. 复核小目标过滤参数与 conf（当前 0.45）。

### P1-3 事件确认帧不足
- 现状：进入/离开各 3 帧确认（[`CROSS_CONFIRM_FRAMES`](../CameraViewer/src/mainwindow.cpp:1163)、[`setConfirmFrames(3)`](../CameraViewer/src/mainwindow.cpp:195)）。
- 优化：改为**时间制**（如 200~300ms）并叠加**位移条件**，避免瞬时抖动触发/取消。

### P2-1 UI/拷贝开销
- `rawFrameGrabbed` 每 5 帧整帧深拷贝（≈6MB）；`frameProcessed` 再拷贝 QImage。
- 优化：UI 更新按**时间**限频（如 10~15fps）或先缩放；改用 `shared_ptr`/`QSharedPointer` 传递帧避免深拷贝。

### P2-2 保存内容不一致
- `visitor_V##` 用 0.3 padding 裁剪，`saveReidImage` 存整帧，`PassengerBook` 存整段序列（0.15 padding）——三处裁剪口径不同。
- 优化：统一裁剪工具与参数；保存时同时落盘 bbox 与特征，便于离线复现与标定。

### P2-3 可观测性
- 优化：每次上/下车事件日志输出 **候选排名与分数**（top-K），并导出 CSV，便于阈值标定与回归测试。

## 四、建议的目标架构（身份优先）

```
GrabThread: 检测(ROI) → 跟踪 → 【唯一】区域穿越判定(轨迹拟合)
                                     │
                                     ├─ 上车事件: 绑定 track→visitor(主键) → 台账登记
                                     └─ 下车事件: 用 track→visitor 直接结账
                                                  └─ ReID 仅做“校验/补救”，附裕度门槛
保存: 统一切图工具(bbox+特征+缩略图)
```

要点：**身份以轨迹为准，外观仅校验**；这样即使 ReID 弱，也能保证上下车配对正确（同一 track 的上下车天然对应）。

## 五、立即可做（低风险）改动清单

1. 合并双状态机/双 ID（P0-1）——**收益最大**。
2. 方向判定改为轨迹斜率 + 位移/时间门槛（P0-2）。
3. `maxMissed`/画廊阈值改按时间并加位置约束（P1-1）。
4. 事件确认改时间制（P1-3）。
5. 日志输出候选排名（P2-3），用于后续 ReID 标定。
6. 若继续做视觉 ReID：按 §P0-3 微调 OSNet 并重新标定阈值（当前深度后端已接入、默认关闭，可在设置中开启做 A/B）。
