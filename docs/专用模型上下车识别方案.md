# 专用模型上下车识别方案（面向「车门正上方俯视 + 匿名重识别」）

> 目标：用**专用模型 + 数据闭环**，把「上/下车识别」的准确率从当前"能用但依赖区域与场景"提升到可交付水平。
> 依据：本项目现有代码与数据（`CameraViewer/src`、`save_images/...`）+ 公开数据集调研结论。

---

## 1. 现状基线与痛点（可量化）

| 环节 | 现状 | 实测/证据 | 痛点 |
|---|---|---|---|
| 检测 | 场景专用 `yolo26n`（TensorRT 640×640） | `detect ≈ 10ms/帧`（专用模型）；通用 `yolov8n` 在本场景 person 置信度仅 **0.02~0.06** → 不可用 | 部分时段/视角下**召回为 0**（大量 `NO detections`） |
| 跟踪 | 自研 IoU + 卡尔曼 + ReID 多阶段 | 有 `Track N matched via stage 3` 记录 | 轨迹**易断裂（ID 切换）**，需"接近点接力"兜底 |
| ReID | 手工 1958 维（HSV 直方图 + 梯度 + 身形）；OSNet 512 维（仅离线用） | 下车比对出现 `best=0.741 vs 次佳=0.728（差距 0.013）` | 俯视/着装相近时**区分力不足**，核销可能选错 |
| 方向判定 | 完整穿越 + 区域级半程接力 + 区域外接近点 + 方向兜底 | 离线复验 3/3 正确（`102229=上车、102326=下车、102439=上车`） | 依赖**区域与人物轨迹重合**；区域偏了只能走宽松判定 |
| 端到端帧率 | 采集 25fps，处理受 ReID 影响 | `[Perf] detect=5~12ms, track+reid=0~1ms`（无目标时） | 有人时 `track+reid` 成为主要开销 |

**已有现场数据资产（本次统计）**

| 数据 | 数量 | 用途 |
|---|---|---|
| 「人物片段」视频 `save_images/clips/*.mp4` | **89 段 / 22,926 帧**（1080p） | 检测微调、跟踪评测、上下车事件样本 |
| 上下车整段序列 `reid/passenger/*/` | **67 个序列**（每段 20~30 张裁剪） | ReID 正/负样本对、动作样本 |
| 访客帧 `2026*/visitor_V*/` | **75 个目录** | 跨时段同人/异人样本 |
| `person_*` 抓拍目录 | 17 | 进出边界样本 |
| 台账 | `passenger_book.json`（历史 60 个乘客 ID）、`visitor_records.json` | 身份标注与核销 ground-truth 参考 |
| 合计体积 | 705 MB | — |

> 关键结论：**现场数据足以支撑第一轮模型微调**；公开数据集主要用于**预训练与算法验证**，因为不存在"垂直俯视 + 双目深度 + 车门上下车 + 匿名计费"四位一体的对标数据集。

## 2. 总体技术路线

```
[公开数据集预训练]                     [现场数据微调]                 [部署]
RAPiD/CEPDOF/LOAF/WEPDTOF  ─┐
PMOF(车内俯视)              ├─► 检测/跟踪主干 ─► 现场 22.9k 帧微调 ─► ONNX ─► TensorRT engine
Top-View Head-Shoulder     ─┘
TVRID / TDPI-B / BV-Person ────► ReID 主干(俯视头肩) ─► 现场 67 序列 + 75 访客帧微调 ─► ONNX 嵌入
                                                          │
                                    ┌─────────────────────┴──────────────────────┐
                                    │  上下车判定融合：检测框轨迹 + 头肩朝向 + 区域时序  │
                                    │  （完整穿越 / 接近点接力 / 方向兜底，已在代码中）    │
                                    └────────────────────────────────────────────┘
```

三大子任务与数据集映射：

| 子任务 | 首选数据 | 辅助数据 | 产出 |
|---|---|---|---|
| **A. 俯视人体/头肩检测** | Top-View Head-Shoulder（3.9k/2.1k） | RAPiD、CEPDOF、LOAF、WEPDTOF、MW-R/HABBOF | 人体框 +（可选）头肩框/关键点，提升"看不到脸"时的定位与朝向 |
| **B. 车内乘客检测与动作** | **PMOF**（19,696 帧 / 31 段 / 67 人，旋转框 + 跟踪 ID + 动作标签） | — | 车内俯视检测/跟踪先验；"上/下车"动作标签 → 方向分类先验 |
| **C. 俯视匿名 ReID** | **TVRID**（4× D455 同步 RGB-D，86 身份）、**TDPI-B/L**（俯视深度头肩，公交场景） | BV-Person（114k/18k id，鸟瞰预训练）、DetReIDX（含 90° 视）、AG-ReID.v2 | 俯视头肩 ReID 主干（可 RGB / RGB-D 融合），直接替换手工作者 |

## 4. 数据闭环（本项目最大优势）

现有程序已在自动产出**高质量业务数据**，只需补齐"半自动标注 + 评测"：

### 4.1 采集（已具备）
- `clips/人物片段_*.mp4`：有人即录、无人分段（含完整穿越过程的候选）
- `reid/passenger/P#_{上车|下车}_*/`：上下车整段序列
- `2026*/visitor_V#/{上车|下车}_*/`：按次穿越归档
- 日志：判定依据（`CROSSING DECISION`）、ReID 候选（`top候选/次佳/差距`）、`[Perf]`

### 4.2 待补齐的脚本（建议放置在 `tools/`）
| 脚本 | 作用 | 输入 → 输出 |
|---|---|---|
| `tools/build_det_dataset.py` | 检测微调集：抽帧 + 用现有模型预标注 + 只保留高置信、人工复核 | `clips/*.mp4` → `datasets/det/images, labels`（YOLO 格式） |
| `tools/build_reid_dataset.py` | ReID 训练集：按 `visitor_V#`/`passenger` 序列构造同人/异人三元组 | 序列目录 → `datasets/reid/{train,val}.txt` |
| `tools/build_action_dataset.py` | 动作（上车/下车）分类集：用片段 + 轨迹方向自动打弱标签，人工复核 | `clips` + `logs` → `datasets/action/*.mp4|frames` |
| `tools/annotate_gold.py` | 生成**gold 清单**（片段 → 上/下车/无穿越） | 人工标注 json |
| `tools/eval_boarding.py` | 上下车判定评测（准确率/召回/误判率），复用 `offline_clip_check` 逻辑 | gold 清单 → 指标报告 |

### 4.3 标注规范（统一口径）
- 框：水平框（YOLO 格式）；如用旋转框（RAPiD/PMOF 风格）记录 `cx,cy,w,h,angle`
- 身份：`visitor_V#` / `P#`（跨片段同人同 ID，人工核对）
- 事件：`boarding` / `alighting` / `pass`（未穿越）
- 可选：头肩框、进出侧（A/B）、进出边界帧号

## 5. 训练与部署流水线

```
① 数据准备（上表脚本）
② 训练
   检测：ultralytics YOLOv8/v11n（本机已装 torch 2.13 + ultralytics 8.4）→ 现场微调
   ReID：OSNet x1.0（MSMT17 预训练）→ TVRID/TDPI-B 预训练 → 现场序列微调
   动作：轻量时序分类（TSM/TSN 或 3D-CNN-lite），输入头肩序列
③ 导出：PyTorch → ONNX（opset 12）→ trtexec 生成 engine
④ 部署：替换 model/ 下文件；用 AppConfig 切换（PreferOnnx/OnnxPath/reidModelPath）
⑤ 回归：offline_clip_check + eval_boarding.py 做 A/B 对比，指标不达标即回滚
```

本机已验证可用：`ultralytics 8.4.112 + torch 2.13 + onnx 1.22`，`yolov8n.onnx` 导出成功（12.2MB，输出 `[1,84,8400]` 与现有解析兼容）。

## 6. 评估协议与验收指标

| 维度 | 指标 | 当前基线 | 目标 |
|---|---|---|---|
| 检测 | mAP@0.5 / **召回@conf0.45** / 小目标召回 | 部分时段召回 0 | 召回 ≥ 0.95（车门口区域） |
| 跟踪 | MOTA / IDF1 / **ID Switch 次数** | 频繁切换（需接力兜底） | ID Switch 下降 ≥ 50% |
| ReID | Rank-1 / mAP（俯视跨上下车） / **最佳-次佳差距** | 差距可低至 0.013 | 差距 ≥ 0.05 的占比 ≥ 80% |
| 业务 | 上下车判定**准确率/召回/误判率** | 依赖区域（区域偏则判不出） | 准确率 ≥ 0.95（gold 清单） |
| 工程 | 端到端帧率 / 崩溃率 / 内存增长 | 检测 10ms；ReID 为主开销 | ≥ 10 fps 处理，长稳 24h 无崩溃 |

## 7. 里程碑路线图

### P0（1~2 周，**不依赖外部数据集**，可立刻做）
1. 用现有 **22,926 帧** + 半自动预标注，微调检测模型（先固定视角/光照域）；
2. 落地 `tools/eval_boarding.py` + gold 清单 → 建立**可回归的业务指标**；
3. 区域自动建议（已在程序的离线判定中输出 `regions_suggested.json`）→ 先把"区域不匹配"这一类误判清零；
4. 继续用 `[Perf]` 定位瓶颈并优化 `track+reid`（降低提取频率、特征前缩放、按需关闭背景扣除）。

### P1（3~6 周，需申请/下载数据集）
5. 申请 **PMOF**（车内俯视，含动作标签）与 **TVRID**（俯视 RGB-D ReID）；下载 **Top-View Head-Shoulder**、RAPiD/CEPDOF/LOAF；
6. 引入**头肩检测分支**（解决"看不清人脸"的定位与朝向）；
7. ReID 主干替换为**俯视头肩 ReID**（TVRID/TDPI-B 预训练 + 现场微调），并接入 `PassengerBook` 核销；
8. 跟踪升级为 **ByteTrack/BoT-SORT** 风格，降低 ID 切换。

### P2（6~12 周）
9. **双目深度融合**（本项目为双目）：RGB-D 双流 ReID（借鉴 TVRID/TDPI HDEG 思路）与深度辅助分割；
10. **动作识别分支**（上车/下车分类器，PMOF 动作标签迁移），与轨迹方向融合投票；
11. 跨域自适应（鱼眼 → 车门俯视）、计费闭环验证与灰度发布。

## 8. 风险与合规

| 风险 | 说明 | 缓解 |
|---|---|---|
| 域差异 | 公开数据集为鱼眼/实验室/公交，非本项目车门俯视 | **现场微调为主**，公开数据只做预训练与验证 |
| 标注成本 | 22.9k 帧全标不现实 | 半自动预标注 + 只标**进出边界关键帧**与困难样本 |
| 隐私/许可 | 人体数据涉隐私 | 选用 privacy-preserving 目标的数据集（TVRID）；CC BY 4.0 遵守署名；现场数据匿名化存储 |
| 算力 | 训练需 GPU、TRT 版本需匹配（本机 TRT 10.3 / CUDA 12.1） | 训练与推理环境分离；engine 与 TRT 版本绑定，随环境重建 |
| 回滚 | 新模型可能在某时段更差 | 配置化 A/B + 指标门禁 + 一键回退旧 engine |

## 9. 立即可执行的第一步（P0 清单，命令级）

```bash
# 1) 检测微调集准备（抽帧 + 预标注，产物待人工复核）
python3 tools/build_det_dataset.py \
    --clips build-CameraViewer-main-Desktop-Debug/save_images/clips \
    --model CameraViewer/model/yolov8n.onnx \
    --out datasets/det --stride 5

# 2) ReID 样本对构建（同人/异人）
python3 tools/build_reid_dataset.py \
    --visitor build-CameraViewer-main-Desktop-Debug/save_images/2026*/visitor_V* \
    --passenger build-CameraViewer-main-Desktop-Debug/save_images/reid/passenger \
    --out datasets/reid

# 3) 业务指标回归（上下车判定准确率）
python3 tools/eval_boarding.py \
    --gold gold/boarding_gold.json \
    --clips build-CameraViewer-main-Desktop-Debug/save_images/clips \
    --checker ./offline_clip_check
```

> 说明：上述脚本目录 `tools/` 与 `gold/` 需新建；`offline_clip_check` 已在本项目可用（`sh build_clip_check.sh` 编译）。
> 建议先把 P0 的三件事做完——**指标可量化 + 区域自动修正 + 检测现场微调**，即可显著提升上下车识别的稳定性；随后再引入公开数据集做 P1 的模型升级。
