# 实时检测“同一人两个框”问题修复（显示过滤 + 在线/离线参数对齐）

## 1. 现象
- **实时画面**：同一名乘客出现**两个检测框**。
- **离线判定**：对同一段录像（如 `人物片段_20261009_171410-171419.mp4`）做检测，只有**一个准确框**。
- `CameraViewer` 与 `CameraViewer_orbbec` 两个程序现象一致（共用同一套检测/跟踪/绘制代码）。

## 2. 根因（已由日志证实）
实时日志出现 `dets=1, persons=2`：
```
[Perf] detect=8ms, track+reid=3ms, dets=1, persons=2
```
即**检测只输出 1 个框，跟踪器却输出 2 条轨迹**。原因链：

1. `PersonTracker::update()` 每帧先把所有轨迹标记为 `detected=false`，只有匹配到真实检测才置回 `true`；
   未匹配的轨迹会用**卡尔曼预测的 bbox 外推**，并在 `trackerMaxMissed=75`（≈3s@25fps）内持续保留。
2. **旧绘制逻辑无差别地画 `persons` 里的所有轨迹**（没有 `if (!p.detected) continue;`），
   于是这条“预测/残留轨迹”被画成第二个实线框。
3. 实时关联阈值偏严（IoU=0.3、内部 ReID=0.72），同一人短暂丢失后的新检测不易复联原轨迹，
   容易分裂出新轨迹（日志中 track 号增长到 32/33），进一步放大“两个框”。
4. 离线判定**每段视频新建跟踪器**（无历史残留），且用 IoU=0.15、内部 ReID=0.62 的宽松关联，
   同一人几乎总能复联原轨迹 → 只保留 1 条轨迹 → 只显示 1 个框。

> 结论：两个框 = 1 个真实检测框 + 1 个卡尔曼预测/未匹配的幽灵轨迹框。

## 3. 修复内容

### 3.1 显示过滤（核心，直接消除多余框）
新增 `MainWindow::shouldDrawTrack()`，绘制循环对每条轨迹先判定：
- 无效框（宽/高 ≤ 0）不画；
- `displayMinConfirmFrames`（默认 3）：轨迹累计命中达到阈值才画，抑制新建/偶发轨迹闪现；
- 本帧 `detected==true` → 画；
- 本帧未检测到（卡尔曼外推）：默认**不画**（`displayOnlyDetectedTracks=true`），彻底消除幽灵框；
  若显式允许（`=false`），则仅在 `missedFrames <= displayMaxMissedFrames`（默认 8）内短暂保留。

### 3.2 在线/离线参数对齐
| 参数 | 旧值 | 新值 | 说明 |
|---|---|---|---|
| `trackerIouThreshold` | 0.3 | **0.15** | 与 `offlinedetectform` 视频判定一致，减少轨迹分裂/ID 切换 |
| `trackerReidThreshold` | 0.72 | **0.62** | 同上，放宽内部 ReID 关联 |

> 注意：`trackerMaxMissed` 仍保持 75，因为它同时服务 ReID 重识别与穿越判定逻辑；
> “幽灵框”由显示层的 `shouldDrawTrack()` 过滤，无需牺牲跟踪逻辑的鲁棒性。

## 5. 新增配置项（`[Display]` 段）
| 键 | 默认 | 含义 |
|---|---|---|
| `OnlyDetectedTracks` | true | 仅绘制真实检测轨迹（推荐，消除幽灵框） |
| `MinConfirmFrames` | 3 | 轨迹累计命中达到该帧数才绘制 |
| `MaxMissedFrames` | 8 | `OnlyDetectedTracks=false` 时，丢失超过该帧数即停止绘制 |

## 6. 关于“有效检测被误过滤”的排查
日志中大量 `Found 1 detections but NONE are valid person after size filtering` 来自
[`PersonDetector::passSizeFilter()`](../CameraViewer/src/persondetector.cpp) 与
[`applyStaticSuppression()`](../CameraViewer/src/persondetector.cpp)：
- `passSizeFilter` 依次校验：绝对像素尺寸 → 宽高比 → 最小高度比 → 最小面积比 → 最大尺寸上限；
- 静态抑制会把“同位置、近零位移、连续命中 ≥ `StaticConfirmFrames`”的检测判为背景误检并丢弃。

这两者用于抑制空场景误检，**本次不修改其判定逻辑**（改动会直接影响召回，需现场标定）。
若现场确认真人被误杀，建议在 `config.ini` 中按场景调 `Inference/MinPersonHeightRatio`、
`MinPersonAreaRatio`、`StaticMaxMoveRatio`、`StaticConfirmFrames`，而非改动代码。

## 7. 验证方法
1. 重新编译两个程序（`app_config.h` 被广泛包含，将触发较多文件重编）。
2. 运行实时采集，观察同一人是否仍有第二个框；
   - 日志 `dets=1, persons=2` 仍可能出现（跟踪器内部仍保留幽灵轨迹用于重识别），但**显示层不再绘制**。
3. 若场景中检测偶发丢帧导致框闪烁，可将 `[Display]/OnlyDetectedTracks=false` 并把
   `MaxMissedFrames` 调到 5~10，短暂保留框以保持视觉连续。
