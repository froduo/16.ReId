# 人物重识别（ReID）检测逻辑梳理

> 代码基线：`CameraViewer/src`（应用版本 v1.1.65）
> 覆盖：特征提取 → 相似度计算 → 跟踪器内匹配 → 访客注册表匹配 → 上下车身份 → 乘客台账比对

---

## 1. 总体数据流与线程模型

```
[采集线程 GrabThread]
  RTSP 取帧
    └─ YOLO 检测 (trt_yolo / persondetector，conf≥0.45，尺寸过滤)
        └─ PersonTracker::update(detections, frame, m_reidExtractor)
              ├─ 卡尔曼预测 → 三阶段匹配(IoU → 预测IoU → ReID)
              ├─ 新建轨迹 / 丢失画廊重识别
              └─ 更新 track.reidFeature 与 reidHistory(5 帧)
    └─ emit frameProcessed(QImage, persons)
                │  (Qt 队列连接，跨线程)
[UI 线程 MainWindow::onFrameProcessed]
  区域进出状态机 Outside→Entering(3帧)→Inside→Exiting(3帧)→Outside
    ├─ matchOrCreateVisitor() → 访客注册表 V##（跨 track 稳定身份，持久化）
    └─ ZoneMonitor::processFrame(persons, rawFrame, regionManager, W, H)
           └─ 完整穿越判定 → boardingEvent / alightingEvent
                  ├─ 上车：PassengerBook::registerBoarding() → P##
                  └─ 下车：IdentityMatchWorker::submit()（后台线程整段序列比对）
                             └─ finished() 回调 → applyAlightingMatch()（UI 线程结算）
```

关键实现位置：

- 检测与跟踪：[`grabthread.cpp`](../CameraViewer/src/grabthread.cpp:107)
- 跟踪器三阶段匹配：[`persontracker.cpp`](../CameraViewer/src/persontracker.cpp:184)
- 访客注册表匹配：[`mainwindow.cpp`](../CameraViewer/src/mainwindow.cpp:945)
- 区域进出状态机：[`mainwindow.cpp`](../CameraViewer/src/mainwindow.cpp:1235)
- 上下车穿越与身份：[`zonemonitor.cpp`](../CameraViewer/src/zonemonitor.cpp:434)
- 下车台账比对：[`identitymatchworker.cpp`](../CameraViewer/src/identitymatchworker.cpp:40)

## 2. 身份体系（四套编号并存）

| 编号 | 生成者 | 生命周期 | 用途 |
|---|---|---|---|
| `trackId` | [`PersonTracker`](../CameraViewer/src/persontracker.h:94)（`m_nextId`，从 1） | 进程内，丢失 75 帧后移入画廊 | 轨迹级关联、绘制 |
| `visitorId`（MainWindow） | [`MainWindow::matchOrCreateVisitor`](../CameraViewer/src/mainwindow.cpp:945)（`m_nextVisitorId`） | **持久化**（visitor_records.json，重启续号，如 nextVisitorId=60） | 区域进出身份、ReID RE-ENTRY、UI 显示 `V##` |
| `visitorId`（ZoneMonitor） | [`ZoneMonitor::matchOrCreateVisitor`](../CameraViewer/src/zonemonitor.cpp:122)（`m_nextVisitorId`，从 1，reset 归零） | 进程内，仅在 ZoneMonitor 内部 | 上下车事件身份、半程续接、冷却判定 |
| `passengerId` | [`PassengerBook::allocatePassengerId`](../CameraViewer/src/passengerbook.cpp:27) | **持久化**（passenger_book.json，next_id） | 乘客台账（上车登记 / 下车核销） |

> ⚠️ 四套编号互不相同步。日志中 `[ZoneMonitor] V1` 与 `[MainWindow] V56` 是**不同体系**；`alightingEvent.evt.visitorId`（ZoneMonitor 号）被当作 `fallbackId` 直接用于 `PassengerBook::isOnboard()` 判断，属于跨编号空间使用，存在回退误核销风险（已在日志中标注）。

## 3. 特征表示

### 3.1 手工多特征融合（在线默认启用）

[`ReIDExtractor::extract()`](../CameraViewer/src/reidextractor.cpp:133) 输出 `1×1958` 的 `CV_32F` 行向量：

| 分量 | 维度 | 算法 | 归一化 |
|---|---|---|---|
| 颜色（上半身 + 下半身） | 960 × 2 = 1920 | HSV 三维直方图 `H15×S8×V8`，`calcHist`，**仅统计前景像素** | L2 |
| 纹理（上半身 + 下半身） | 18 × 2 = 36 | 灰度 Sobel → `cartToPolar` → 梯度方向 mod 180° 幅度加权直方图 | L2 |
| 身形 | 2 | `长宽比 = w/h`、`归一化高度 = h/frame.rows` | 不做归一化 |

分箱从早期的 `30×32×32` 降为 `15×8×8`，用于解决鱼眼俯视下人体像素少导致直方图稀疏、跨朝向相似度塌陷的问题（见 [`reidextractor.h`](../CameraViewer/src/reidextractor.h:17) 注释）。

### 3.2 背景扣除

[`BackgroundModel`](../CameraViewer/src/backgroundmodel.h:24)：固定摄像头维护背景参考图，`前景 = |frame - bg| > 25`（含形态学、可选 CUDA）。

- 仅在"画面基本没人"（前景占比 < 0.15）时以 0.03 学习率更新背景；
- 前景掩码用于：① 直方图跳过背景像素；② 收紧人体框（前景包围盒需 ≥4×4 且面积比 ≥0.20，否则回退整框）；
- 同帧掩码带缓存，避免每个目标重复全帧运算。

### 3.3 深度特征（OSNet，**默认关闭**）

[`DeepReID`](../CameraViewer/src/reiddeep.cpp:54)：ONNX `osnet_x1_0_msmt17.onnx`，输入 128×256 RGB + ImageNet 归一化，全局平均池化 → `512` 维 L2 归一化，余弦相似度（阈值默认 0.50）。

> 现状：`reidUseDeepReid=false`，且**仅离线检测表单使用**；在线管线（GrabThread / MainWindow / ZoneMonitor / PassengerBook）全部使用手工 1958 维特征。
> 另外后端被固定为 `DNN_BACKEND_OPENCV + DNN_TARGET_CPU`（注释写"优先 CUDA"但未实现），一旦开启会明显增加 CPU 负载。

## 4. 相似度计算

[`ReIDExtractor::compare()`](../CameraViewer/src/reidextractor.cpp:306)：

1. **分量比较**
   - 颜色：上下半身各自 `Bhattacharyya` 距离 `d` → 相似度 `1-d`，融合 `0.55×上身 + 0.45×下身`；
   - 纹理：同样 `1-d`，`0.5/0.5` 融合；
   - 身形：`0.6×长宽比相对相似 + 0.4×归一化高度相对相似`（相对差异 `1-|x-y|/max`）。
2. **加权融合**：默认 `颜色 0.30 / 纹理 0.40 / 身形 0.30`（内部自动归一化，可由 `AppConfig` 覆盖）。
3. **抗朝向**：把第二个特征做"上下半身互换"（等效 180° 旋转）再比较，取两次的较大值——对应上车(背向)/下车(面向)的翻转。
4. **多帧融合**：[`averageFeatures()`](../CameraViewer/src/reidextractor.cpp:213) 对多帧逐元素平均，并对颜色块、纹理块重新 L2 归一化。

> 维度不一致时返回 0（视为不相似），避免 OpenCV 抛异常。

## 5. 匹配点一：跟踪器内部（`PersonTracker`）

[`multiStageMatch()`](../CameraViewer/src/persontracker.cpp:184) 三阶段：

| 阶段 | 依据 | 阈值 | 权重处理 |
|---|---|---|---|
| 1 | 当前框 IoU | `trackerIouThreshold = 0.30` | 分数 = IoU |
| 2 | 卡尔曼预测框 IoU | `0.30 × 0.5 = 0.15` | 分数 = predIoU × 0.80 |
| 3 | ReID 特征相似度 | `trackerReidThreshold = 0.72` | 分数 = similarity × 0.60 |

- 所有候选对按分数降序**贪心匹配**；
- 轨迹用于匹配的外观 = 最近 5 帧特征的平均（`REID_HISTORY_SIZE = 5`，[`computeAverageReid`](../CameraViewer/src/persontracker.cpp:131)）；
- **未匹配的检测**先尝试 [`tryReidFromGallery()`](../CameraViewer/src/persontracker.cpp:359) 从"丢失轨迹画廊"恢复原 `trackId`（阈值同为 0.72，且位置距离 < `10 × max(w,h)`），失败才新建 `trackId`；
- **未匹配的轨迹** `missedFrames++`，超过 `trackerMaxMissed = 75` 帧（约 3 s）后连同平均特征移入画廊，画廊保留 `trackerGalleryMaxAgeMs = 10000` ms。

目的：减少"同一人被分配多个 trackId"。

## 6. 匹配点二：访客注册表（`MainWindow`）

区域进出状态机（同一 `trackId` 内）：`Outside → Entering → Inside → Exiting → Outside`，进出均需连续 **3 帧**确认（`CROSS_CONFIRM_FRAMES`）。

确认进入时调用 [`matchOrCreateVisitor()`](../CameraViewer/src/mainwindow.cpp:945)：

1. 若 `m_trackToVisitor` 已有映射 → 直接复用；
2. 否则提取 ReID 特征，遍历 `m_visitors` 中 **`!isInside` 且特征非空** 的访客，取相似度最高且 `≥ reidMatchThreshold(0.65)` 者 → **RE-ENTRY**：复用原 `visitorId`，更新 `enterTime / enterImage / reidFeature`，写 `REENTRY` 事件；
3. 无满足者 → 新建 `visitorId`（`m_nextVisitorId++`，持久化）。

确认离开时 [`updateVisitorExit()`](../CameraViewer/src/mainwindow.cpp:969) 置 `isInside=false`、记录 `exitImage`。

UI 显示 ID = `visitorId`（无则 `trackId`），见 [`mainwindow.cpp`](../CameraViewer/src/mainwindow.cpp:845)。

## 7. 匹配点三：上下车身份（`ZoneMonitor`）

[`ZoneMonitor::matchOrCreateVisitor()`](../CameraViewer/src/zonemonitor.cpp:122)：

- 若 `m_trackToVisitor` 有映射 → 复用；
- 否则遍历自身的 `m_visitorFeatures`，仅对**当前不在 Capturing 状态**（即遍历 `m_channelTracks` 未发现该 visitor 正在采样）的访客做比较，取 `≥ reidMatchThreshold(0.65)` 最高者 → 复用并更新特征，打印 `ReID RE-ENTRY`；
- 否则新建（`m_nextVisitorId++`，从 1 起）。

配套机制（本次新增，用于抑制误判）：

- **完整穿越判定**：起点需在区域一侧边界之外、终点需在另一侧边界之外，才判上车/下车；
- **启动防抖**：连续 2 帧重叠且交集面积 ≥ 0.0012 才开启采样；
- **同人反向冷却**：同一 visitor 在 8 s 内出现相反方向穿越 → `SUPPRESS`；
- **半程续接**：起点已在入口侧之外但未走完全程时记入 `m_pendingStarts`（8 s 有效），换 `trackId` 后重新匹配到同一 visitor 且方向一致时沿用旧起点，保证仍按一次完整穿越结算。

## 8. 匹配点四：乘客台账与下车比对（`PassengerBook` + `IdentityMatchWorker`）

- **上车**：`boardingEvent` → `registerBoarding(preferredId = evt.visitorId, feats = 整段穿越采样特征)` →
  若 `preferredId` 未被占用则沿用，否则自动分配新号 → 台账记录 `passengerId / boardTime / boardImagePath / features`。
- **下车**：`alightingEvent` → UI 线程快照在车模板 → [`IdentityMatchWorker::submit()`](../CameraViewer/src/identitymatchworker.cpp:40) 在后台线程串行比对：
  - 相似度 [`sequenceSimilarity()`](../CameraViewer/src/identitymatchworker.cpp:18)：对**探针序列每一帧**取与模板序列所有帧的最大相似度，再对探针帧求平均（best-avg）；
  - 取最高且 `≥ 0.65` 者为命中；
  - 输出 `top候选` 明细与"最佳/次佳差距"（本次新增，用于识别误匹配）。
- **结算**（[`applyAlightingMatch`](../CameraViewer/src/mainwindow.cpp:337)）：
  1. 命中 → `removePassenger(bestId)`；
  2. 未命中但 `fallbackId` 在台账中 → 按回退身份核销（`matched=false`，标记异常）；
  3. 否则 → 异常下车，保存"异常乘客"图片。
- 台账以 JSON（特征 Base64 + `next_id`）持久化，重启后继续比对；跨会话还会丢弃"维度不兼容"的旧特征（如 1958 维变更）。

## 9. 参数与阈值汇总

| 配置项 | 默认值 | 生效位置 |
|---|---|---|
| `detectorConfThreshold` / `detectorNmsThreshold` | 0.45 / 0.5 | YOLO 检测 |
| `detectorMinPersonHeightRatio` / `...AreaRatio` | 0.08 / 0.005 | 小目标过滤 |
| `trackerIouThreshold` | 0.30 | 跟踪阶段 1/2 |
| `trackerMaxMissed` | 75 帧 | 轨迹丢弃时机 |
| `trackerReidThreshold` | 0.72 | 跟踪阶段 3、画廊重识别 |
| `trackerGalleryMaxAgeMs` | 10000 | 丢失画廊保留 |
| `reidMatchThreshold` | 0.65 | MainWindow RE-ENTRY、ZoneMonitor 身份匹配、PassengerBook 下车比对 |
| `reidWeightColor/Texture/Shape` | 0.30 / 0.40 / 0.30 | 相似度融合 |
| `reidUseBackground` | true | 前景掩码参与特征提取 |
| `reidUseDeepReid` / `reidDeepMatchThreshold` | false / 0.50 | 深度 ReID（仅离线表单） |

代码内常量：`TOTAL_DIM = 1958`、`H/S/V = 15/8/8`、`TEX_BINS = 18`、`REID_HISTORY_SIZE = 5`、`CROSS_CONFIRM_FRAMES = 3`。
ZoneMonitor 内部可调：`m_startConfirmFrames = 2`、`m_minOverlapArea = 0.0012`、`m_reverseCooldownMs = 8000`、`m_edgeMargin = 0.0`、`PENDING_START_GRACE_MS = 8000`。

## 10. 现状问题与改进建议

1. **编号空间混用**：四套 ID 并存，`alightingEvent.evt.visitorId` 直接被用作 `passengerId` 回退核销，可能核销错误乘客。建议下车回退改为"按本次任务关联的 boarding 记录"或引入统一身份注册表（`CameraViewer_dongqia` 已有 `VisitorRegistry` 实现可移植）。
2. **在线特征区分力有限**：仅手工颜色/纹理/身形，相似着装时"最佳与次佳差距"很小 → 误匹配。建议开启 OSNet 深度特征（需现场标定阈值与后端性能）或在 `compare` 中加入深度-手工双通道融合。
3. **阈值双轨**：跟踪器 0.72、上下车/台账 0.65，跨朝向相似度波动大。建议按离线数据集（`offline_reid_*` 脚本）批量标定 ROC 后统一取值。
4. **特征副本不同步**：MainWindow `VisitorRecord::reidFeature` 与 ZoneMonitor `m_visitorFeatures` 各自维护、独立更新（RE-ENTRY 时整段覆盖），同一人可能在不同模块得到不同匹配结果。
5. **配置未接线**：`AppConfig.zoneMinDisplacement` 无 `setMinDisplacement()` 调用，实际由 ZoneMonitor 内部默认值控制（且仅在无区域信息时生效）。
6. **深度后端为 CPU**：`DeepReID::load()` 固定 `DNN_TARGET_CPU`，与注释不符；启用前需改为 CUDA 或评估性能。
7. **背景更新条件苛刻**：前景占比 < 0.15 才更新背景，长时间有人时会长期不更新，可能导致前景掩码退化。
