## 1. 项目概览

本项目面向 **HX-CCD23 双目客流统计终端**（华芯智云 foorir），在 RTSP 视频流上完成
**人员检测 → 多目标跟踪 → ReID 身份识别 → 区域穿越（上车/下车）判定**，
并将客流数据按 **动恰 3DV6 AI HTTP 协议**（客流时段聚合上行）上报平台。

| 项目 | 说明 |
|------|------|
| 主程序 | `CameraViewer`（HX-CCD23 人员检测 ReID 系统） |
| 动恰对接版本 | `CameraViewer_dongqia`（主程序的**独立副本**，新增协议上行，不改动原程序） |
| 相机 | HX-CCD23，RTSP：`rtsp://192.168.99.10:8554/live/camera`（H.264 / 1920x1080 / 25fps） |
| 相机 HTTP 账号 | `admin / hf123456`（端口 80；OpenCV 默认配置中为 `admin / admin123`） |
| 上行平台 | `https://footfall.dongqia.com`，账号 `dongqia01 / 123456` |

## 4. 系统架构与数据流

```
RTSP 相机 (HX-CCD23)
      │
      ▼
CameraController ──► GrabThread（采集线程）
      │                 │  ├─ PersonDetector（YOLO/TensorRT 检测）
      │                 │  ├─ PersonTracker（IoU+卡尔曼+ReID 多阶段跟踪）
      │                 │  └─ ReIDExtractor（HSV 颜色直方图特征）
      │                 ▼
      │        frameProcessed(QImage, QVector<TrackedPerson>)
      ▼
MainWindow（UI 线程）
      ├─ ImageView 显示 / 绘制叠加
      ├─ RegionManager（多边形区域，归一化坐标）
      ├─ VisitorRegistry（全局稳定身份，一人一 ID）
      ├─ ZoneMonitor（通道 A/B 端点穿越 → 上车/下车事件）
      ├─ VisitorLog（person_records.csv / visitor_events.csv / visitor_records.json）
      ├─ SaveImageWorker（后台线程保存图像）
      └─ FlowAggregator（分钟时段聚合 + 单人上下车时间线）
              │
              ▼
        HttpUplink（POST JSON，revision 取大 / 幂等 / 离线 spool / 固定间隔重试）
              │
              ▼
        footfall.dongqia.com
```

## 9. 动恰客流上行协议实现要点

协议原文：`动恰3DV6 AI HTTP 新对接协议20260911.pdf`，实现严格对齐其 0~6 章。

| 协议要求 | 实现位置 |
|----------|----------|
| `POST /api/passenger-flow/interval-aggregate`，`application/json` | [`HttpUplink::makeRequest()`](../CameraViewer_dongqia/src/httpuplink.cpp:262) |
| 回 2xx 且**响应体非空**才算成功，否则重发 | [`HttpUplink::handleSuccess()`](../CameraViewer_dongqia/src/httpuplink.cpp:305) |
| 一件报文 = 一分钟；`interval_s=60`；`end_ts_s=start_ts_s+60` | [`FlowAggregator::buildAggregate()`](../CameraViewer_dongqia/src/flowaggregator.cpp:434) |
| 按 `(master_sn, batch_date, start_ts_s)` 整件替换 | [`IntervalAggregate::idempotentKey()`](../CameraViewer_dongqia/src/dongqia_protocol.h:158) |
| 同一分钟多次到达按 `revision` 取大 | [`HttpUplink::enqueueInterval()`](../CameraViewer_dongqia/src/httpuplink.cpp:118) |
| 幂等：重复投递终态不变 | 幂等键 + `m_bestRevision` 去重 |
| 每个时段只发最新版 | [`HttpUplink::enqueueInternal()`](../CameraViewer_dongqia/src/httpuplink.cpp:171) |
| 一件一件发，前一件确认后再发下一件 | [`HttpUplink::onReplyFinished()`](../CameraViewer_dongqia/src/httpuplink.cpp:349) |
| 设备侧最多留 2 天，超期清理 | [`HttpUplink::pruneSpool()`](../CameraViewer_dongqia/src/httpuplink.cpp:520) |
| `raw = final + repeat + non_customer`（严格恒等式） | 构造即保证，见 [`FlowAggregator::onEnter()`](../CameraViewer_dongqia/src/flowaggregator.cpp:124) |
| 各维度分桶之和 = 所属块 count；`not_measured` 单独一格 | [`orderedBucketRows()`](../CameraViewer_dongqia/src/flowaggregator.cpp:400) |
| 驻留时长按**进店时间**归时段 | [`FlowAggregator::onLeave()`](../CameraViewer_dongqia/src/flowaggregator.cpp:196) |

### 9.1 单人上下车精准识别

每个访客（ReID 稳定身份）的上下车事件都会：

- 写入 `visitor_log/visitor_events.csv`（`BOARDING` / `ALIGHTING`，含时间与方向）；
- 通过 `FlowAggregator::personTracked` 打印完整时间线，例如
  `V3 上车2次/下车2次 | 进入4/离开4 | 首次 … | 最近 … | 累计驻留 …s`；
- 以 `person_flow_event` 报文上行（含 `visitor_id`、方向 `B->A`/`A->B`、
  `enter_ts_s`/`exit_ts_s`、`dwell_seconds`、`reid_similarity`、抓拍 Base64）。

方向定义（对齐 [`ZoneMonitor`](../CameraViewer_dongqia/src/zonemonitor.h:17)）：
通道顶端 A、底端 B，**B→A = 上车**，**A→B = 下车**；跨帧确认 `confirmFrames=3` 防抖。

## 13. 稳定性说明

- **崩溃修复**（仅副本）：跟踪框越界/退化时（例如卡尔曼预测出负坐标），标签背景矩形与画面求交后为空，
  `cv::addWeighted` 在 0×0 空 ROI 上抛异常。修复方式：跟踪框与画面无交集时跳过标签绘制；
  背景矩形或 ROI 为空时跳过背景混合，见 [`drawActiveIdOnCvMat()`](../CameraViewer_dongqia/src/mainwindow.cpp:605) 与
  [`OfflineDetectForm`](../CameraViewer_dongqia/src/offlinedetectform.cpp:293)。
- **一人一 ID**：`VisitorRegistry` 为跨轨迹稳定身份的**唯一来源**，保证
  显示 ID == 跟踪 ID == 上下车 ID；支持轨迹丢失后续接与身份合并，避免上车/下车被拆成多条。
- **防抖**：`confirmFrames=3` 确认穿越；同人重复上下车去抖窗口 `CROSSING_DEDUP_MS=2500`；
  穿越续接宽限 `PENDING_GRACE_MS=8000`。
- **自动重连**：`GrabThread` 连续失败触发 `deviceLost`，`MainWindow` 最多重连 60 次、间隔 5 秒。
